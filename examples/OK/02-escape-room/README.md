# OK：鍵を使って脱出できるマップを作る

最初の題材は、閉館後の水族館からの脱出ゲームです。AIが部屋の並びや手がかりを作ります。舞台を観測船に変えたければ、`brief.md` の代わりに `inputs/ship.md` を渡します。ファクトリーはそのままです。

## AIが作るのはシナリオとマップ

AIは、`agents/builder.md` の指示と `spec.md` のルールに沿って `game.json` を書きます。検査する `check.py` と遊ぶための `play.py` は同梱済みです。どちらも `game.json` をデータとして読み、AIが書いたコードを実行することはありません。

`agents/reviewer.md` は、手がかりを読んで次の行き先が分かるか、別のAIにレビューさせる場合の指示書です。この作例の実行時には使いません。

## 鍵あり・鍵なしの2通りでマップを探索する

1. 必須項目や部屋数を調べます。存在しない部屋への移動があれば、探索する前に不合格にします。
2. 「今いる部屋」と「鍵を持っているか」の組み合わせを、開始地点から幅優先探索でたどります。出口に着けない場合や、最短経路が4手未満の場合は不合格です。
3. 鍵を拾わない条件でもう一度探索します。鍵なしで出口に着けてしまうマップも不合格です。

不合格なら、「鍵を拾わずに出口へ行ける経路があります。」のように理由をAIへ返し、最大3回まで作り直させます。検査器とプレイヤーで同じ移動処理を使っているため、鍵を拾う前後の判定がずれません。

経路の条件を満たしていても、面白いゲームとは限りません。手がかりの面白さや、すべての寄り道から引き返せるかは判定しません。

## 生成して遊ぶ

Python 3 と認証済みの Codex CLI を用意し、リポジトリのルートで実行します。

```sh
python3 examples/OK/factory.py examples/OK/02-escape-room
python3 -B examples/OK/02-escape-room/play.py "出力先のパス/game.json"
```

2行目には、1行目の `出力先:` に表示されたパスを指定します。表示された移動コマンドを入力して進み、`quit` で終了します。別の題材で試すときは `--brief` で入力ファイルを差し替えられます。

```sh
python3 examples/OK/factory.py examples/OK/02-escape-room --brief examples/OK/02-escape-room/inputs/ship.md
```

発表では、まず生成されたゲームを遊んでみせ、そのあと「どんな失敗を自動検査で弾いたか」を話すと伝わりやすくなります。
